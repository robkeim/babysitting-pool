# A Member's address is picked from the French national address base and the Area is derived from it

Free-text Area and address gave inconsistent Areas ("Eastside", "East side") and addresses a Sitter could not always put into a GPS (#111). A Member now searches for their address and must pick a suggestion from the Base Adresse Nationale (BAN), served by the Géoplateforme geocoder; the Area is derived from the pick and cannot be edited.

**Service.** `https://data.geopf.fr/geocodage/search` with `autocomplete=1`. Free, no API key, French state open data, documented limit 50 requests a second per IP (checked 2026-10-29; a live response also carried `x-ratelimit-limit-second: 1`, so the first slice confirms the real limit under load). Its response gives `label`, `city`, `citycode` (INSEE), `depcode`, `postcode` and `type`. Paid and metered vendors (Google Places, Mapbox, Geoapify) were rejected: the budget is $0 and BAN is free and built for this. Nominatim's public instance forbids autocomplete, and self-hosting needs infrastructure ADR 0018 does not have. Browser autofill attributes on the field are added regardless, at no cost.

**Backend proxy.** The browser calls `GET /api/address-suggestions?q=` on our API, which calls BAN. No CSP change (ADR 0014 keeps `default-src 'self'`), BAN never sees a Member's IP, and our per-Member rate limit protects the free service. The query text is a partial home address, so it is on the never-log list (ADR 0010). Short timeout. If BAN is down or slow, the profile address cannot be changed until it is back; there is no manual fallback. Only the small share of Members editing an address during an outage is affected.

**What is accepted and stored.** Only suggestions of type `housenumber` or `locality` (a lieu-dit; rural France often has no house numbers) can be picked; a bare street or a whole commune cannot. The profile stores the BAN `label`, the commune name, the INSEE code and the postcode. No coordinates: they are one more sensitive value for Erasure to clear, and a GPS app takes the label. A separate optional **instructions** field (300 characters; "apt 3, ring at X, park across the street") holds what a geocoder cannot.

**Area.** The commune name plus the département number, for example "Amiens (80)". Commune names are not unique across départements, and a postcode is not one-to-one with a commune (Paris has twenty), so a postcode would split one commune into several Areas. Grouping and equality use the INSEE code; the text is a label. The Area is read-only and the profile shows it as what other Members will see. Arrondissement-level Areas for Paris, Lyon and Marseille are a possible later special case.

**Limitation: France only.** BAN covers France, including overseas départements. A Member cannot save an address elsewhere. This is deliberate for now and is stated in the spec and under the address field.

**Privacy.** Sending a Member's address to a vendor is a new decision against ADR 0014, which treats addresses as sensitive. We accept it because BAN is a public service and the address is sent while searching and once on pick, not on every page load. Erasure (#60) cannot reach anything BAN retains. An opt-out of address verification is deferred: if a Member objects, it needs its own decision, and a manual path would bring back the inconsistency this ADR removes.

**Consequences.** Instructions follow the address everywhere: copied onto the Request at posting, shown only to the counterparty once Claimed, deleted by Erasure, and never in Notifications, logs, Admin views or email. Unlike the address, editing them does not drop a claim, as with free-text notes (spec §4). The project is not live, so the database is dropped rather than backfilled: no existing free-text Area is migrated.
