# SQLite persistence is guarded by a concurrency token and one transaction per handler, and tested against real SQLite and the real stack

Persistence uses EF Core code-first migrations, checked in and applied at API startup (one SQLite file, one instance, so no migration race); CI fails on model/migration drift. SQLite runs with WAL, `foreign_keys=ON` and a `busy_timeout`, set in the connection setup so tests and production behave identically.

The first-claim-wins race, and every other Request or Credit Account transition race, is settled by an optimistic concurrency token (integer `Version`) on the persistence model. The loser's `DbUpdateConcurrencyException` rolls back its transaction and maps to `409 Conflict` ProblemDetails; there is no retry. We rejected a hand-written `UPDATE ... WHERE Status='Posted'` because it moves a business rule into SQL and must be repeated per transition. One handler is one transaction (a single `SaveChanges` covering Request, Credit Accounts and Ledger rows), and SQLite triggers reject `UPDATE` and `DELETE` on the Ledger so append-only holds below the app.

Time comes from .NET's `TimeProvider` (`FakeTimeProvider` in tests); domain methods take `now` as a parameter and never read a clock. There is no in-memory persistence adapter: tests use real SQLite built from the real migrations, and a second adapter would diverge on exactly the concurrency and constraint behaviour we most need to test. Email goes through an `IEmailSender` port with a fake outbox adapter for dev, tests and E2E; the production provider is chosen in the authentication work.

Playwright E2E runs the real API and SPA with no API mocks. Each Playwright worker starts its own backend in an `E2E` environment with its own temp database and `FakeTimeProvider`, so tests can jump time without interfering in parallel. Test-only endpoints (set the clock, read the email outbox, seed state through the application layer) exist only in that environment. Backups are periodic consistent SQLite snapshots stored off the host with a tested restore; the destination and interval belong to Deployment.
